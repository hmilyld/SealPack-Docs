界面把整个流程切成五步，每一步只出现一件事：

```
① 主程序  →  ② 合并  →  ③ 加密  →  ④ 打包  →  ⑤ 执行
```

- **步骤条可点** —— 任意跳步、回看、只重跑某一步。走过的步骤标成「已完成」。
- **每步下面有一行实时摘要** —— 主程序文件名 / 勾选了几个程序集 / 启用了几项保护 / 排除了几项。
- **面板全部留在 DOM 里**，只切换显示 —— 来回翻页时滚动位置、展开的目录、正在编辑的模板都不会丢。
- **跳过是正常路径** —— 没勾选内容的步骤执行时自动跳过，不会中断流程。
- **失败即停** —— 某一步失败会停下并保留日志，后续步骤不再执行（它们依赖前一步的产物）。

## ① 主程序

选择要处理的 `.exe`。它所在目录会成为后面两步的扫描根目录 —— 合并要合并进谁、打包要打包谁，
都由这一个选择决定。

- **版本号**可以点「自动探测」从 exe 的文件版本信息里读（`GetFileVersionInfo`），也可以手填。
- **安装包口令**留空表示不加口令。它**以明文**保存在工程文件里，见[数据与安全](/docs/security)。
- 换主程序时，若新主程序在**另一个目录**，原先勾选的合并项会自动移除并提示 ——
  那些文件已经不在扫描范围内，留在列表里既看不见也取消不掉。

<Figure src="/shots/01-setup.png" alt="主程序步骤：选择 exe、版本号与安装包口令" caption="① 主程序 —— 一次选择决定了后面三步的作用范围" />

## ② 合并

左侧是文件树，右侧是已选文件清单。文件树的三个点击区、搜索与筛选在[文件树与选择](/docs/file-tree)里单独讲。

要点只有一句：**主程序本身不会出现在树里**，它不需要被合并进自己。
执行前会自动把主程序备份为 `<主程序名>.bakup`，且该备份默认不进入安装包 ——
合并与加密都是原地覆盖主程序，这个备份是唯一的退路。

## ③ 加密

先选一档整体强度（**不加密 / 基础 / 标准 / 严格**），再按需微调单项。
开关与参数会直接生成 ConfuserEx 配置，一项保护都不启用时本步会被自动跳过。

每个选项的语义、默认值与它写进模板的内容见[加密选项](/docs/encrypt-options)。

<Callout tone="note">

若你在「高级」里手工改过模板，开关就不再覆盖它。此时点预设会先问一句「是否同时用这些选项覆盖模板」，
想交回开关托管就点提示条上的「用当前选项覆盖模板」。

</Callout>

## ④ 打包

上半部分是**不参与打包的文件**，下半部分是**安装包选项**：压缩格式与 LZMA 参数、打包模式、
安装包加密与签名、安装行为、完整性校验。详见[打包与排除项](/docs/package)与[打包选项](/docs/package-options)。

## ⑤ 执行

三个阶段的清单，每行显示当前摘要、状态徽标、产出文件与「单独执行」按钮。

- **全部执行** —— 合并 → 加密 → 打包 顺序跑，过程中显示「正在执行 N / 3」。
- **单独执行** —— 只重跑某一步（例如只重跑打包）。
- **产出文件**是按钮，点一下在资源管理器中定位。它不猜文件名：靠执行前后对比输出目录找出实际产出。
- **运行日志**在窗口底部，stdout / stderr / 系统提示分行显示并标注来源；可复制、清空、折叠。

执行期间左侧工程列表会被锁定 —— 中途切换工程会让正在跑的阶段落到另一个目标上。
细节见[执行与日志](/docs/run)。

## 步骤之间共享的那份摘要

「勾选了几个程序集 / 启用了几项保护 / 排除了几项」这件事在界面上出现**两次**：
步骤条每步下面一行，以及执行页每个阶段一行。两处读同一份数据，但渲染时机不同 ——
步骤条每次改动都重算，执行页那几行只在**工程首次渲染**与**阶段执行结束**时算。

这曾经产生过一个 bug：用户在 ②③④ 里逐项配好，切到 ⑤ 执行，看到的却是刚建工程时的快照
（「未勾选程序集」「未启用任何保护」「排除 0 项」）。修复的办法是让所有改动路径统一走
`syncStepSubs()`，它同时刷新两处；回归探针用一条不变量守着它们不会不一致。

<Callout tone="pitfall" label="推论">

以后凡是「同一个事实在界面上出现多次」，要么让它们走同一个渲染函数，要么在一处集中刷新 ——
否则必然出现这种「一半新一半旧」。

</Callout>
