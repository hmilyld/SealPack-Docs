## 一行拆成三个点击区

「点错了」是文件树最常被抱怨的事：想展开却勾上了整个目录，想勾选却把树折起来了。
SealPack 的做法是把一行的点击面拆开，各管各的：

| 区域 | 点击行为 |
| --- | --- |
| 展开箭头 | 只展开 / 折叠，**不改任何勾选** |
| 勾选框 | 只勾选 / 取消（目录含子级），**不折叠** |
| 名称 | 只把焦点移过去，**不改勾选**；双击才等于「激活」 |

三个热区互不重叠，也互不代理 —— 点箭头永远不会改变已选清单，点名称永远不会让目录合上。

<Callout tone="note" label="键盘">

文件树是 roving tabindex：整棵树只有一个焦点位，用 <Kbd>↑</Kbd> <Kbd>↓</Kbd> 移动、
<Kbd>→</Kbd> <Kbd>←</Kbd> 展开 / 折叠或进入 / 返回上层、<Kbd>空格</Kbd> 或 <Kbd>Enter</Kbd> 切换勾选。
Tab 键只在树与右侧清单之间跳，不会在几十个节点之间爬。

</Callout>

## 三条找文件的路径

不同的心理模型对应不同的入口，三条都保留：

1. **我知道大概在哪** → 直接展开目录看。树默认**不过滤**，结构完整。
2. **我知道类型** → 点类型 chip 收敛，例如只看 `.dll`。
3. **我知道名字** → 搜索框。命中高亮、祖先自动展开，而且**搜索前后会记住并恢复你手工折叠的状态**。

勾完再用「只看已选」复核一遍，或点「勾选当前结果」把筛选后可见的文件批量勾上。

## 右侧清单

- 可筛选、可逐项 <Kbd>×</Kbd> 移除，也可以「全部移除」。
- 主程序本身不会出现在树里 —— 它不需要被合并进自己。
- 清单里每一项都带相对路径，粘贴进别的工具时不用再拼一次。

## 视图变了 ≠ 勾选变了

这是两件事，而且经常被写混：

- **勾选变了**（`onChange`）要写回工程、触发防抖保存；
- **视图变了**（`onView`）—— 折叠目录、改筛选条件 —— 只改变「看得见几个」，**不该触发落盘**。

但底栏「当前显示 N 项」必须跟着视图刷新。这个 bug 真的发生过：折叠目录后底栏数字不动，
用户以为自己折叠失败。所以树导出两个回调，各管一头。

<Callout tone="pitfall" label="给改代码的人">

扫描目录与刷新排除项都是异步的，而它们写回的目标是模块级状态。切换工程时若旧请求晚于新请求返回，
就会把上一个工程的目录树挂到当前工程上。两者各有一个单调递增的 epoch，回来时对不上就丢弃。

**两个计数器必须分开** —— 勾选文件会触发排除项刷新，共用一个计数器会让在途的扫描自我作废。
另外每条早退路径都要把 `scanning` 落回 false，否则一个被作废的请求会把「扫描中…」永久留在步骤条上。

</Callout>
