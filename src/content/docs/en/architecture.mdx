## Stack and shape

**A Windows desktop app**: Rust backend (Tauri 2) + React 18 + TypeScript frontend, with components and
theming from Fluent UI React v9 + Griffel and state in Zustand. There is one Fluent design; light and dark
follow Windows.

Tauri rather than Electron for a direct reason: the app drives three external command-line tools, reads and
writes local files, and wants window materials, while the render layer is just "a settings UI plus a log
panel" — no need to ship a whole browser runtime for that.

## Data flow

```
User flips a switch in the wizard
      │
      ├─ option written to project.encryptOptions / packageOptions
      │
      ├─ if generated == true → invoke render_encrypt_config / render_package_script
      │        (Rust defaults.rs renders the template text) → written back to the project
      │
      ├─ 600 ms debounce → invoke save_project → projects/<id>.json
      │
      └─ press Run → invoke run_stage
               │
               ├─ Rust: save_project first (disk is authoritative), then the pipeline
               ├─ resolve the toolchain per stage → back up the executable (first run) → write scratch config / script
               ├─ spawn the child process, emit "pipeline:log" per stdout / stderr line
               ├─ emit "pipeline:stage" with stage status
               ├─ package stage: expand ${files} / ${installDelete} per artifact
               │    → snapshot the output directory before and after → write the baseline manifest / checksums
               └─ append to Project.buildHistory (no passwords)
```

The frontend holds no template semantics: it collects switches and the template is always produced by Rust.
That constraint makes it impossible for "the options on screen" and "what actually gets written" to drift.

## Invariants

Each of these is a bug that actually happened. Read them before touching the related code.

### Options and templates

**Adding a config option means changing only the schema.** Encrypt and package options are declared in
`ENCRYPT_GROUPS` / `PACKAGE_GROUPS` in `src/types.ts` with `kind` / `def` / `when` / `writes`; the UI renders
from it and the regression probe asserts from it. Do not hand-write a widget for one option.

**Templates are generated only by Rust.** The browser preview has no Rust, so `preview/render.ts` mirrors
`defaults.rs`; when they drift, the preview shows a template users will never get. `check:render-parity`
compares them character by character.

**Inno boundary values live at the top of `defaults.rs`.** `LZMA_DICT_MIN_KB` / `LZMA_DICT_MAX_KB` /
`LZMA_THREADS_MAX` / `SLICE_MIN_BYTES` / `SLICE_MAX_BYTES` / `SLICES_MIN` / `SLICES_MAX` are copied from
the official documentation, and `preview/render.ts` has constants with the same names.

**Upgrade packages branch only in the package stage.** `defaults.rs` generates one template; `packaging.rs`
expands `${files}` / `${installDelete}` / `${artifactSetup}` / `${artifactCode}` / `${artifactLabel}` /
`${runSection}` per artifact. Merge and obfuscation never know upgrade packages exist.

### Async and state

**Async writes back into shared state need an epoch guard.** `ensureTree` / `refreshIgnores` write back into
store state. If an old request returns after a newer one when switching projects, the previous project's
tree lands on the current one. Each has its own monotonically increasing `epoch`; a mismatch discards the
result. **The two counters must stay separate** — checking a file triggers an excludes refresh, and a shared
counter makes the in-flight scan invalidate itself. Every early-return path must also settle `scanning`.

**Snapshot the project before a long task.** `buildStore.runStage` / `runAll` capture `project.id` on entry
and validate it before every write-back. The project rail is disabled while running, but shortcuts and
programmatic paths can still switch.

**Settle the debounced save before switching projects.** The save is debounced by 600 ms and the callback
captures the project; `select` / `refresh` call `flush()` first, and deleting the current project uses
`discard()`.

**One fact shown twice must refresh together.** The step summaries and the run-page summaries both come from
`src/lib/summaries.ts`; do not compute them separately in components.

### Styles and theme

**There is exactly one theme.** `ThemeProvider` uses `FluentProvider` + `createLightTheme` /
`createDarkTheme`; the state is `system | light | dark`, stored in `localStorage["sealpack:theme"]`.
**Do not bring back `data-skin` or a second skin.**

**Tokens have two layers.** App-level sizes / type / radii live in `src/styles/tokens.css`, semantic colours
in `src/theme/semantic.ts`; component colours use Fluent `tokens.*`. No raw hex in components; spacing only
4/8/12/16/20/24/32; font sizes only 11/12/14/18/20; radii only 4/6/8/10.

**The window background has three copies.** `WINDOW_BG` in `src/theme/colors.ts`, the first-frame inline
scripts in `index.html` / `preview.html`, and `backgroundColor` in `src-tauri/tauri.conf.json`. Change one
and you must change all three.

### Platform and toolchain

**Registering a Tauri command takes two steps**: define it in `commands.rs` **and** add it to the
`invoke_handler!` list in `lib.rs`.

**Toolchain resolution falls back three levels**: user settings > bundled `resources/tools` > user download
directory. The third level is mandatory — the bundled directory is read-only when the app lives under
`Program Files`.

**A bundled tool must match the declared download version.** Resolution is "bundled first, then
downloaded", so an old bundled copy silently shadows the correct version.

**The global shortcut table never calls `stopPropagation`**, or overlays cannot close.

**Both halves of `visible: false` are required.** The frontend calls `show()` after the first frame and Rust
has a 1.5 s fallback; the inline bootstrap in `index.html` depends on Tauri injecting a CSP hash/nonce at
build time (the CSP is `script-src 'self'`).

### Data

**Project JSON has no serde defaults.** The app writes every field, so a missing field means the file was
damaged and should fail loudly rather than quietly gain a default. The only exception is
`Project.schemaVersion`, which `store.rs::migrate_project` uses to add `buildHistory` / `buildOptions` and
bump to 3. `Settings::load` falls back to defaults on a parse failure but leaves a trace on stderr.

**Every value goes through a whitelist.** Project JSON is hand-editable, so enum values pass a whitelist
before being written into a template and unknown values fall back to the default (`defaults.rs::pick`).

## Desktop design trade-offs

The browser engine's defaults are the main source of "web feel". `desktop.ts` replaces them one by one with
desktop conventions:

| Suppressed browser behaviour | Why |
| --- | --- |
| `Ctrl+R` / `F5` / `F7` / `F12` | reload and devtools |
| `Ctrl+P` / `Ctrl+F` / `Ctrl+U` | print / find / view source |
| `Ctrl+Shift+I/J/C` | devtools and element inspection |
| `Ctrl` `+` / `-` / `0` and `Ctrl+wheel` | browser zoom — a fixed-density desktop tool has no concept of zoom, so it is suppressed rather than remapped |
| dragging content out / files in | blocks `dragstart` and `dragover` / `drop` |
| the native context menu | replaced by the hand-drawn menu |
| `Backspace` without focus | blocks "back" |
| selecting UI text | `body` defaults to `user-select: none`; inputs, script editors and the run log opt back in |

Metrics lean on Fluent / WinUI 3:

| Item | Value | Basis |
| --- | --- | --- |
| Title bar height | 40 px | Fluent caption area; minimise / maximise / close on the right |
| Caption buttons | 46 px wide × full height × square | Fluent caption buttons; close hover `#C42B1C` |
| Status bar | 28 px | local tools put status at the bottom of the window, not in the title bar |
| Body / line height | 14 px / 20 px | Fluent body text; 30 px tree rows, 32 px controls |
| Radii | 4 px controls / 8 px panels | Fluent's 4/8 system |
| Motion | 83 / 167 / 250 ms | Fluent motion |
| Focus ring | 2 px double stroke | Fluent focus is a double stroke, not a coloured glow |
| Cursor | arrow everywhere | a hand cursor is a web habit |

Overlays always pair a shadow with a 1 px border so they do not smear on a light background. Fonts are the
system Segoe UI Variable / Cascadia Mono, because the CSP is `default-src 'self'` and remote fonts cannot be
loaded at run time.
