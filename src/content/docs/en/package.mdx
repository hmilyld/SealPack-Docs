## Artifact type

The **Artifact** control on the Package step decides what this build produces:

- **Full installer**: every selected file;
- **Upgrade package**: only changes relative to the baseline; removals go to `[InstallDelete]`;
- **Both**: two ISCC runs from the same template, two exes.

Baselines, diffing and target-machine checks are covered in [Full and upgrade packages](/en/docs/upgrade).

## Full-package file scope

The full package takes the whole main-program folder, minus files that should not ship:

**Automatic items** are derived from the previous steps and cannot be removed here:

- assemblies to merge — they are already inside the main executable;
- the `<main>.bakup` backup — a rollback copy, not an artifact;
- an output directory inside the root — so the previous build is not packed into the next one.

**Custom items** accept relative paths and Inno wildcards (`*.pdb`, `docs\*`). They are shown as chips, not
expanded into the tree. Excludes cannot contain commas: Inno separates `Excludes` entries with commas.

## The main executable is packed once

For a full package, `${files}` expands into two `Source` lines:

```ini
Source: "${root}\${exe}"; DestDir: "{app}"; Flags: ignoreversion
Source: "${root}\*"; Excludes: "${ignore},${exe}"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs createallsubdirs
```

The wildcard line must exclude the main executable or the same file is packed twice. An upgrade package
expands to one `Source` line per changed file and keeps the relative directory.

## Packaging options

Five fixed groups: compression, packaging mode, encryption and signing, install behaviour, and integrity.
See [Packaging options](/en/docs/package-options) for each option. Three common misunderstandings:

1. **Compression is "algorithm + level" in one value** (`lzma2/max`).
2. **An LZMA dictionary size of 0 omits the line**, letting Inno choose based on the compression level.
3. **Installer encryption defaults to `yes`**; Inno's own default is `no`.

## Checksums

When an algorithm is selected, the build writes a checksum file in `sha256sum` format:

```bat
certutil -hashfile installer.exe sha256
:: or
sha256sum -c checksums-sha256.txt
```

The file name is per artifact so full and upgrade builds do not overwrite each other:

- `checksums-<algorithm>.txt`
- `checksums-upgrade-<algorithm>.txt`
- `checksums-both-<algorithm>.txt`

The list only contains files produced or rewritten by this build, not old files already in the directory.
